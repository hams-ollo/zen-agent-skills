# Contributing

Thanks for considering a contribution to Zen Agent Skills. Please read the first section before writing anything, because this project rejects work for a reason most repositories do not have.

## The bar: no skill ships cold

**A skill earns a place in this kit only after it has been used on real work.**

The lifecycle is: draft it, use it on a real task in a real repository, iterate from what that use exposed, and only then bless it as shipped. A skill that has never been run is a guess about what an agent needs, and guesses are exactly what this kit exists to replace.

The practical consequence: **a well-written skill for a workflow you have not actually performed will be declined**, no matter how good the prose is. This is the most common way a contribution goes wrong here, and it is nobody's fault if it was never written down, which is why it is the first thing on this page.

What this means for you:

- **Proposing a new skill?** Open an issue first and describe the recurring problem, not the solution. If it is a real recurring problem, the next question is whether you have solved it by hand enough times to know what the procedure actually is.
- **Improving an existing skill?** Say what you ran, what happened, and what the skill should have done. Evidence from a real run outweighs any argument about how it reads.
- **Fixing something broken?** Just send it. Bugs, dead links, wrong commands, and stale claims need no ceremony.

Speculative skills are not thrown away, they are parked. See [`ROADMAP.md`](ROADMAP.md), where planned skills wait until there is a real use case. Two of them are explicitly held until they have been needed twice.

## What this repository is

A library of portable agent skills plus the tooling that distributes them. It has no runtime application, no database, no service, and no third-party Python dependency, and those absences are the point. Anything that adds one needs a strong argument.

The canonical rules live in [`AGENTS.md`](AGENTS.md). It is written for AI agents but is the most direct description of how the repository works, so read it whether you are one or not.

## Before you open a change

Run all four. They are stdlib-only, so there is nothing to install:

```bash
python scripts/validate-skills.py
```

```bash
python -m unittest discover -s tests -p "test_*.py"
```

```bash
python .tasks/validate.py --strict
```

```bash
python scripts/build-adapters.py --dry-run
```

CI runs the same commands on Linux, macOS, and Windows across the supported Python range. Running them locally first just saves you a round trip.

## Conventions

- **One source of truth per skill.** A skill's logic lives only in its `.agents/skills/<name>/SKILL.md`. Cursor rules and Copilot prompts are generated by [`scripts/build-adapters.py`](scripts/build-adapters.py). Never hand-edit a generated adapter.
- **Links must resolve where the skill is used, not only where it is written.** A skill ships as a directory beside its siblings and the rules module, without this repository around it. A link may reach its own files, a sibling skill, or `.agents/rules/`, and nothing above that. The validator fails on violations, because this exact defect once shipped `house-review` with no rubric.
- **No tool lock-in in a skill body.** Gate anything harness-specific behind a clearly labeled optional section.
- **Writing style** follows [`.agents/rules/house-style.md`](.agents/rules/house-style.md): sentence-case headings, relative links, named sources, no em-dashes. That module is swappable by adopters, so point at it rather than restating it.
- **Cross-platform.** Target Windows, macOS, and Linux. Prefer `pathlib`, and never assume POSIX symlinks are available.

## How work is tracked

The repository dogfoods the same system it ships. Atomic work items live in [`.tasks/`](.tasks/), the ordered plan in [`ROADMAP.md`](ROADMAP.md), and completed work in [`CHANGELOG.md`](CHANGELOG.md). You do not need to author a task file for a small fix, but for anything larger it is the fastest way to get agreement on scope before you spend time.

## If you are an AI agent

Read [`AGENTS.md`](AGENTS.md) in full first. It defines a deliberately narrow reading protocol: this file, your one assigned task file, and only the files that task names. Do not scan the whole `.tasks/` directory or read other agents' task files.

## Reporting problems

Use the issue templates. The one labelled "a skill behaved unexpectedly" is the most valuable report this project can receive, because it captures the gap between what a skill's description promised and what the agent actually did.

For anything security-relevant, do not open a public issue. Follow [`SECURITY.md`](SECURITY.md) instead.
