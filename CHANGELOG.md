# Changelog

Completed work for Zen Agent Skills, newest first. This is the append-only ledger for the spec-driven task workflow: when a task in [`.tasks/`](.tasks/) is finished, its file moves to `.tasks/done/` and one dated line is added here referencing the task id.

## Releases

### v0.1.0 (2026-07-29)

Tagged at [`1917dbe`](https://github.com/hams-ollo/zen-agent-skills/releases/tag/v0.1.0) on 2026-07-29, after `chore-0021` prepared the release and the author authorised publishing it. The ordered publish steps that were followed, and the repository topics that were applied, are recorded in [`chore-0021`](.tasks/done/chore-0021-release-hygiene-v0-1-0.md).

Contents, derived from the task log below (2026-07-23 to 2026-07-29) rather than from memory, as measured on 2026-07-29:

- **19 skills** under [`.agents/skills/`](.agents/skills/): the setup, contract, build, verify, and documentation spine, plus the two handoff skills.
- **Two swappable lenses** under [`.agents/rules/`](.agents/rules/), [`house-style.md`](.agents/rules/house-style.md) and [`review-quality.md`](.agents/rules/review-quality.md), shipped alongside the skills, because a skill that composes a lens is not self-contained without it.
- **Distribution tooling**: [`install.py`](scripts/install.py) with its `--profile` axis and reversible manifest, [`build-adapters.py`](scripts/build-adapters.py) for Cursor and VS Code or Copilot, and [`validate-skills.py`](scripts/validate-skills.py), which enforces the parts of the skill schema that otherwise fail at the consumer.
- **Nine approved behavioral contracts** under [`docs/spec/`](docs/spec/), with the conformance, verification, readiness, and characterization records that sit beside them.
- **84 tests** under [`tests/`](tests/), with CI running every check on Linux, macOS, and Windows against Python 3.11 and 3.14.

`0.1.0` rather than `1.0.0`, deliberately: this is one maintainer's working library, two catalog skills are held unbuilt until they have been used twice, and the install story has an open portability question, since `npx skills` copies only each skill's `SKILL.md` and leaves its lens reference resolving to nothing (`chore-0020`, `feat-0034`).
