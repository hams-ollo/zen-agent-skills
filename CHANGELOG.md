- [x] (2026-07-25) Closed `feat-0020`: authored the `doc-sync` skill (ROADMAP Epic B #9), the documentation half of the delivery spine. It detects documentation drift by checking prose claims against repository facts, classifying every document by property as current-state (correctable with explicit per-finding approval), contract (report-only, because a disagreement there means the code is wrong) or ledger (skipped, because history is not drift), with an unclassifiable document defaulting to contract so the failure mode is inaction. Dry run is the default rather than a flag, every reported finding names the fact that grounds it, an ungroundable suspicion is not reported at all, and each finding carries a stable `D-NNN` id plus a `grounded` or `suspected` confidence so dismissing a false positive costs one identifier. Applying leaves an audit trail naming the claim corrected, the evidence, and the confidence it carried; vendored third-party material is never edited even when its path is named. Composes `doc-revise` by reference for editing discipline. Built against `docs/spec/doc-sync.md`, the second spec drafted by `spec-author` and explicitly approved before decomposition, after two open questions were resolved into the contract. The roadmap line crediting an upstream `document` workflow was corrected: no such skill was ever vendored here, so this was authored rather than folded in. Dogfooded and iterated; draft pending user sign-off before blessing.
